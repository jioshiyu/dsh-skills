# 成本纪律（先量后改，量必须带出处）

> 来源：2026-10-25 携程赛题 3257 万 token 复盘 + caveman 的 Accounting & Evidence 纪律。
> 一句话：**先看 token 结构再谈优化；每个数字都要能说出"谁测的、按哪天的什么价"。**

## 1. 记账三要素

| 要素 | 要求 | 反例 |
|---|---|---|
| 数值 | token / 金额分开写，别写"省了 30%" | "省了 30% token"（谁的 30%？） |
| 证据标签 | 见下表，汇总时不许换标签 | 把本地估算当厂商账单 |
| 价格表 + 日期 | 写清 `模型对比.md` 某天某档价 | "按 0.2 元/M"（对不上任何一档） |

证据标签（照抄口径，别自造）：

- `measured` 本地机制直接数的；`provider_reported` 厂商 usage 字段返回的（最优）；
- `inferred` 分词器/模型估的；`benchmark_counterfactual` 受控 fixture 差值；
- `observed` 前后对比（相关，不是因果）；`verified` 有强制校验方法且记录在案；
- `unpriced` 无公开价 → **写 unpriced，不许写 0**（0 会被误读成免费）。

禁止：跨模型/跨时段/跨任务外推；把牌价当账单；丢掉失败的尝试（负结果也要记）。

## 2. 结构算术（决定优化顺序）

- 每轮都重读一遍上下文 → **缓存读取 ≈ 步数 × 上下文**。所以：**减步数 > 压输出 > 压读图**。
- deepseek-flash 空闲价（`模型对比.md` 2026-10-25）：未命中 ¥1/M、缓存 ¥0.02/M、输出 ¥4/M。
- 实测样本（携程 7 条用例，3257 万 token，¥1.03）：缓存 63%、**输出 33%**、未命中输入 4%；
  输出只占总 token 的 0.26%，但在钱上占 1/3 —— 体积占比 ≠ 花钱占比。
- 速算口诀：**输出省 30% ≈ 省 ¥0.1/次**；**命中率掉 1pp ≈ 多花 ¥0.32**（一次赛题量级）。

## 3. 红线：别动前缀

- 同一会话里改 system prompt / 工具集 / 模型 → 缓存全冷，缓存价只有未命中价的 **1/50**（输出价 1/200）。
- **外部压缩代理不要装**（如 caveman proxy）：它靠改写请求见效，会破坏前缀匹配；它宣称的 33.2% 是**输入侧**收益，基准是 log/JSON/diff 这类读取内容。压缩 skill（只压输出）可以试。
- 改任何配置前先问一句：这会不会让下一轮缓存未命中？

## 4. 事中闸门（事后台账救不了已经烧掉的钱）

```powershell
python D:\Projects\workbench\scripts\wb.py usage --guard 3000000   # 超阈值 → 非零退出
python D:\Projects\workbench\scripts\wb.py usage --record          # 收尾写 health.md 台账
```

- 大任务（预估 >1M token）开工前记一次基线，之后**每 20 轮**自查一次；
- 触线后**先停手**：切便宜模型（GLM-5.3-Flash / flash 空闲档）→ 停截图改 `dom_summary` → 合并往返，而不是继续试错。

## 5. A/B 判据（三绿才留，否则卸）

1. 固定 fixture、跑 **≥3 次取中位数**（单次任务方差极大：同一批题 0.4–1.35M 都有）；
2. 同时记三项：**输出 token / 缓存命中率 / 质检是否全绿** —— 缺第二项，结论无效；
3. 事前写死 pass：输出降 ≥20% **且** 命中率降 <1pp **且** 用例全绿；
4. 失败与负结果一并留档，不许只报成功的。

## 6. 对外汇报 checklist

数字前先答：① 证据标签；② fixture 或记录链接；③ 计数器与价格日期；④ 质量测试与失败数；
⑤ 牌价 ≠ 账单；⑥ 不许跨模型/任务/时段外推；⑦ 无依据就写 0 或 `unpriced`。

## 坑（踩过）

- 旧稿把缓存价写成 0.2 元/M（实为 0.02），金额整体虚高 10 倍 → 后来所有"哪个插件省钱"的排序都建在错基数上；
- 只看"总 token 降没降"会漏掉真问题：携程那次是**步数**失控 + 读图随缓存重复计费，不是话多。

## 7. 图片四规则（读图必须回本）

读图的真实成本不是"一张 2k token"，而是**它随缓存被后续每一步重复计费**；所以要么产出、要么别读。

1. **读了就要有产物**：每张图落盘到 `docs/images/` 并被文档引用，或写出一条文本化结论（表格/取值/断言），二者必居其一；
2. **能用结构化文本代替就不读图**：`dom_summary` / `office_read` / 表格抽取优先；
3. **图要能再生成**：提交"生成脚本 + 数据"而不是裸 PNG（示例 `assembly-notebook/shared/screen_png.py`）；
4. **收尾自检**：这次读的图，有几张变成了仓库里的图或断言？0 张 = 这次图片投入没回本，记一笔。

## 8. 体积与账单是两回事（2026-10-25 三次实测）

| 会话 | 总 token | 输出 | 输出占体积 | 输出占费（flash 空闲价） |
|---|---:|---:|---:|---:|
| 携程赛题 | 32.57M | 84.8k | 0.26% | ≈33% |
| 算法 15 题 | 83.29M | 291k | 0.35% | ≈34% |
| 汇编 21 题 | 22.57M | 176k | 0.78% | ≈57% |

- **体积看输入、账单看输出**：命中率越高（99%+），输出的钱占比越大；
- 减步数仍排第一（缓存读取 ≈ 步数 × 上下文），但"话多"在高命中会话里不再是小钱；
- 汇报用表格替段落，长代码只贴改动的行。
