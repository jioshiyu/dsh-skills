# 复习资料工业化

## 一句话

**别"转写资料"，要"产出三件可验证的东西"**：考点地图、速查卡、可判分自测题。资料只是原料，不是产物。

## 四个阶段（顺序不能反）

| 阶段 | 产出 | 质量门 |
|---|---|---|
| 1 登记来源 | `来源.md`：文件名/章节/日期/页数 + 证据标签（measured/reported/inferred） | 每个数字能溯源；读不清的标"未核实" |
| 2 建考点地图 | 按**考试大纲/教材章节**组织，不按文件组织 | 每个考点一句话定义 + 出现频率/难度 |
| 3 写速查卡 | 一张卡 = 一个考点：定义 / 公式 / 典型题 / 易错点 | 卡片不超过 1 屏；公式带单位与适用条件 |
| 4 出可判分题 | 每题：题干 + 答案 + 解析（**分开存**） | 至少覆盖 80% 考点；能一键批改 |

## 反模式（写了等于没写）

- 把 PDF 整篇 OCR 成 Markdown 就当笔记（原料换了个容器）；
- 答案和题干写在一起（自测时等于开卷）；
- 只堆知识点不做题（考场上是"会背不会算"）；
- 不写来源与日期（下次复习无法判断是否过期）。

## 文件布局（与 workbench 文档体系一致）

```
docs/复习/<科目>/
├── 00-来源.md          # 文件清单 + 采集日期 + 未核实项
├── 10-考点地图.md      # 按大纲分节，链到速查卡
├── 20-速查卡.md        # 一卡一考点（type: reference）
├── 30-题库.md          # 题目（不含答案）
├── 31-答案.md          # 答案 + 解析（与 30 分开）
└── 40-错题本.md        # 做错的题 + 错因 + 复习日期
```

front-matter 统一：`type: tutorial|howto|reference|explanation`、`topic`、`related`、`summary`
（这样 `wb.py docs` 会自动生成导航、`wb.py site` 会出网页）。

## 自测怎么"可判分"

不用造判题系统，用三条低成本规则：

1. **答案分离**（30/31 两个文件），复习时只看 30；
2. **每题一个"关键步骤"**：解析里第一行写"这题考什么"，批改时先对这一步；
3. **错题回填**：做错的题抄进 40-错题本，写上错因（概念错 / 计算错 / 审题错），
   下次复习只刷错题本 + 考点地图里标红的节。

## 工具映射

| 需求 | 用什么 |
|---|---|
| 读 PDF/PPT/DOC（含扫描件） | `office_read`（自带 OCR 与乱码检测） |
| 读截图/图表 | `modlens_read_image`，读完必须落成文字结论（见 cost-discipline 图片四规则） |
| 建索引/检索 | `kb_search` + `wb.py index` |
| 生成复习网页 | `wb.py site`（mermaid 出知识点关系图） |
| 版本与备份 | `git`（每轮复习一次提交，错题本随进度长） |

## 收尾自检

- [ ] 每个考点都有：定义 + 一道可判分题？
- [ ] 30/31 分离，答案里第一行写"考什么"？
- [ ] 来源与日期齐全，未核实的明确标出？
- [ ] `wb.py docs --check` 过（无断链、无缺 front-matter）？
