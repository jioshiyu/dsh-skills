# 复习资料工业化

## 一句话

**别"转写资料"，要"产出三件可验证的东西"**：考点地图、速查卡、可判分自测题。资料只是原料，不是产物。

## 四个阶段（顺序不能反）

| 阶段 | 产出 | 质量门 |
|---|---|---|
| 1 登记来源 | `来源.md`：文件名/章节/日期/页数 + 证据标签（measured/reported/inferred） | 每个数字能溯源；读不清的标"未核实" |
| 2 建考点地图 | 按**考试大纲/教材章节**组织，不按文件组织 | 每个考点一句话定义 + 出现频率/难度 |
| 3 写速查卡 | 一张卡 = 一个考点：定义 / 公式 / 典型题 / 易错点 | 卡片不超过 1 屏；公式带单位与适用条件 |
| 4 出可判分题 | 每题：题干 + 答案 + 解析（**分开存**） | 至少覆盖 80% 考点；能一键批改 |

## 反模式（写了等于没写）

- 把 PDF 整篇 OCR 成 Markdown 就当笔记（原料换了个容器）；
- 答案和题干写在一起（自测时等于开卷）；
- 只堆知识点不做题（考场上是"会背不会算"）；
- 不写来源与日期（下次复习无法判断是否过期）。

## 文件布局（与 workbench 文档体系一致）

```
docs/复习/<科目>/
├── 00-来源.md          # 文件清单 + 采集日期 + 未核实项
├── 10-考点地图.md      # 按大纲分节，链到速查卡
├── 20-速查卡.md        # 一卡一考点（type: reference）
├── 30-题库.md          # 题目（不含答案）
├── 31-答案.md          # 答案 + 解析（与 30 分开）
└── 40-错题本.md        # 做错的题 + 错因 + 复习日期
```

front-matter 统一：`type: tutorial|howto|reference|explanation`、`topic`、`related`、`summary`
（这样 `wb.py docs` 会自动生成导航、`wb.py site` 会出网页）。

## 自测怎么"可判分"

不用造判题系统，用三条低成本规则：

1. **答案分离**（30/31 两个文件），复习时只看 30；
2. **每题一个"关键步骤"**：解析里第一行写"这题考什么"，批改时先对这一步；
3. **错题回填**：做错的题抄进 40-错题本，写上错因（概念错 / 计算错 / 审题错），
   下次复习只刷错题本 + 考点地图里标红的节。

## 工具映射

| 需求 | 用什么 |
|---|---|
| 读 PDF/PPT/DOC（含扫描件） | `office_read`（自带 OCR 与乱码检测） |
| 读截图/图表 | `modlens_read_image`，读完必须落成文字结论（见 cost-discipline 图片四规则） |
| 建索引/检索 | `kb_search` + `wb.py index` |
| 生成复习网页 | `wb.py site`（mermaid 出知识点关系图） |
| 版本与备份 | `git`（每轮复习一次提交，错题本随进度长） |

## 收尾自检

- [ ] 每个考点都有：定义 + 一道可判分题？
- [ ] 30/31 分离，答案里第一行写"考什么"？
- [ ] 来源与日期齐全，未核实的明确标出？
- [ ] `wb.py docs --check` 过（无断链、无缺 front-matter）？

## 高星纯文档项目的六个共性（拿来就用）

参考了 GitHub 上几类高星"纯文档"项目的组织方式（Coding Interview University 的 checklist 学习路径、
system-design-primer 的单主题单文件、keyvanakbary/learning-notes 的目录组织）：

1. **目录即学习路径**：README 顶部一张从上到下的清单，每项带预计工时，勾完=学完；
2. **单页单一概念**：一屏内讲完、可独立阅读，不依赖"见上文第 3 节"；
3. **图先于字**：一张 mermaid 关系图 + 3~5 行说明，比五段文字快；
4. **术语表 + FAQ**：回看成本最低的两个部件；
5. **可复制的最小例子**：能直接跑的命令/代码，而不是"参考实现"；
6. **来源与许可写清楚**：每个结论标出处，仓库加 LICENSE（纯文档也要）。

## 复习包生成清单（做完打勾）

- [ ] `00-来源.md`：文件清单 + 采集日期 + 未核实项
- [ ] `10-考点地图.md`：按考纲分节，每节链到速查卡
- [ ] `20-速查卡.md`：一卡一考点，卡内四件套（定义/公式/典型题/易错）
- [ ] `30-题库.md` / `31-答案.md`：**分文件**，解析第一行写"考什么"
- [ ] 卡片原子化：一卡一问，答案 ≤ 3 行（可直接导出成 Anki/FSRS 的 csv：`问题,答案,标签`）
- [ ] 间隔重复：用 FSRS/Anki 排程（不自己写算法），每轮只刷"到期 + 错题本"
- [ ] `40-错题本.md`：错因分三类（概念/计算/审题），下次只刷标注项
- [ ] `wb.py docs --check` 通过；`wb.py site` 能出网页

## 实战复盘：软件测试路径测试复习包（2026-10-26）

第一次真跑这条流水线，五个教训：

1. **教学大纲 ≠ 复习包**。大纲是"能力体系 + 学时 + 验收"（如《本科四年算法竞赛教学大纲》的五层梯度），
   复习包是"考点 + 卡片 + 题库"。两者要**交叉引用**，不要合并成一个四不像。
2. **文件名前缀就是学习顺序**：`00-来源 → 10-考点地图 → 20-速查卡 → 30-题库 → 31-答案 → 40-错题本`，
   数字前缀让目录排序 = 复习路线，省掉一张导航表。
3. **题库页要写"先做完再看"**，答案单独一个文件；否则自测等于开卷。
4. **二手整理稿的四个通病**（本次实测）：没有引用来源、没有版本/日期、答案与题干混排、例题没有判分口径。
   复习包的价值就是把它们补上：来源表、日期、分离答案、"这题考什么"。
5. **版本陷阱**：同一主题常见 `_修改版` / `_终极定稿` / `(1)` 多个文件并存。来源登记必须写
   "与另一版未逐条 diff"，不要默认最新版最全。

## 材料台账（防止"读过就忘"）

同一目录下材料一多，最大的浪费不是"整理得不好"，而是**某些材料从没被处理过却以为处理过了**。
所以在 `docs/复习/00-台账.md` 维护一张表，每份材料只有四种状态：

| 状态 | 含义 | 由谁改 |
|---|---|---|
| ✅ 已成品 | 复习包已填完且 `wb.py review --check` 通过 | 人 |
| 🟡 已骨架 | `wb.py review --scaffold` 生成、待填 | 工具 |
| ⬜ 未处理 | 还没动（**默认状态**） | 人 |
| ⛔ 不处理 | 明确不要（无关文件/编译产物），**必须写理由** | 人 |

规则：
1. 新资料进来**当天**就在台账加一行，不要靠记忆；
2. `review --check` 只保证"已成品"的质量，**管不了"未被处理"的材料**——台账必须人工维护；
3. 同主题多版本先 diff，只留一份进复习包，另一份在来源表写"未采用及原因"；
4. 每月底清一次"未 diff"的重复文件（多半能删）。

## 来源可信度分级（比"二手稿"更细）

| 级别 | 例子 | 用法 |
|---|---|---|
| 教材/真题 | 教材原文、真题卷 | 可直接背、可引用 |
| 自己整理 | 自己的笔记 | 可背，引用时注明"自整理" |
| 二手整理稿 | 学长/网络流传的"终极定稿" | 只用来练，引用前回教材核 |
| **AI 生成** | 文末自述"部分内容由 AI 生成" | **必须标注**；只当练习，结论一律回教材核 |

> 实测：第 9 章数据流那份 docx 末尾自述"部分内容由豆包工作 AI 生成"——这种必须在 `00-来源.md` 里写明，
> 否则你会在考场上引用一个没人核过的定义。

## 工具自身也会出错：写进报错手册

跑复习包流水线时踩的坑（scaffold 抽不到标题、check 误报、related 撞名）
一律写进 `workbench/docs/报错手册.md`，不要只在本轮对话里解决——
下次换个科目重跑时，这些坑会再出现一次。
